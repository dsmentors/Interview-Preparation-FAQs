Agentic AI concepts

Q1What is agentic AI?

Agentic AI refers to AI systems that pursue goals with a degree of autonomy: they plan, choose actions, use tools, observe the results and adapt, with limited step-by-step human direction. The focus is on the whole system that completes a task end to end, not on a single model answering a prompt.

Typical traits are goal orientation, planning, tool use, memory, adaptation to feedback and, in many designs, collaboration between several agents.

Q2What is the difference between generative AI and agentic AI?
Generative AI Agentic AI
What it does Produces content (text, code, images) in response to a prompt Works toward a goal by planning and taking actions
Interaction One prompt, one response Many steps, with decisions in between
Tools and memory Optional Central
Human role Writes each prompt Sets the goal, then supervises or approves
Example “Write an email reply” “Handle this support ticket: check the order, issue a refund within policy and reply to the customer”

Agentic systems are usually built on top of generative models.

Q3What is the difference between an AI agent and agentic AI?

An AI agent is a single component: an LLM with tools, memory and a loop. Agentic AI is the broader approach or system in which one or more agents, workflows, tools, memory and guardrails work together autonomously toward goals. A single agent can be agentic, but agentic AI often means multiple coordinated agents plus the infrastructure around them.

The terms are used loosely in industry, so in an interview define how you are using them.

Q4What are the key characteristics of an agentic system?
  • Autonomy: it decides the next steps without being told each one.
  • Goal-directed behavior: it works toward an outcome, not just a reply.
  • Planning and reasoning: it breaks problems down and adjusts the plan.
  • Tool use: it acts on external systems through APIs and tools.
  • Memory and context: it remembers what happened and what it learned.
  • Adaptation: it reacts to feedback and failures.
  • Collaboration: it can work with other agents and with people.
Q5What are the levels of autonomy in agentic systems?

One common way to describe it, from least to most autonomous:

Level Description Example
0. No autonomy The model only answers; humans do everything else A plain chatbot
1. Assistive The model suggests actions, a human performs them Code suggestions
2. Supervised The agent acts, a human approves each important step Draft email sent only after approval
3. Conditional The agent acts on its own within limits and escalates exceptions Refunds up to a set amount
4. High autonomy The agent runs end to end with oversight by monitoring and audit Automated incident handling

Choose the level based on the risk of the task, not the capability of the model.

Q6Why has agentic AI become practical now?
  • Stronger reasoning models that can plan and follow multi-step instructions.
  • Reliable tool (function) calling and structured outputs.
  • Longer context windows that hold more state and tool results.
  • Standard protocols such as MCP that make tool integration easier.
  • Frameworks and tracing tools for building and monitoring agents.
  • Lower cost per token, which makes multi-step runs affordable.
Q7When should you use a workflow instead of an autonomous agent?

Prefer the simplest design that works:

  • Use a workflow (predefined steps with LLM calls and code) when the task is well understood. It is cheaper, faster, easier to test and more predictable.
  • Use an autonomous agent when the number and order of steps cannot be known in advance and the model must decide as it goes.

Many production systems are a hybrid: a fixed workflow skeleton with agentic steps only where flexibility is needed.

Workflow and design patterns

Q8What are the common agentic workflow patterns?
Pattern Idea Use when
Prompt chaining Break a task into a fixed sequence of LLM calls, each using the previous output The task splits cleanly into steps
Routing Classify the input and send it to a specialized path or model Different input types need different handling
Parallelization Run subtasks at the same time (sectioning), or run the same task several times and compare (voting) Speed, or higher confidence
Orchestrator-workers A central LLM splits the task dynamically and delegates to worker LLMs The subtasks cannot be predicted in advance
Evaluator-optimizer One LLM produces, another critiques, and the loop repeats Clear quality criteria and room for improvement
Q9What are the four agentic design patterns?

A popular summary of the core patterns is:

  1. Reflection: the agent critiques and improves its own output.
  2. Tool use: the agent calls external tools and APIs.
  3. Planning: the agent breaks the goal into steps and orders them.
  4. Multi-agent collaboration: several specialized agents work together.
Q10Explain the orchestrator-workers pattern.

A central orchestrator LLM analyzes the task, decides which subtasks are needed (not fixed in advance), assigns them to worker LLMs or agents, and then combines their results. It suits tasks such as changing code across many files or researching a broad topic from several sources.

import json

def orchestrator(goal):
    plan = llm("Split this goal into independent subtasks. Return a JSON list.\nGoal: " + goal)
    results = [worker(task) for task in json.loads(plan)]   # workers can run in parallel
    return llm("Combine these results into one final answer:\n" + "\n".join(results))

def worker(task):
    return agent_loop(task, tools=tools_for(task))

Here llm and agent_loop are placeholders for your model client and agent loop.

Q11Explain the evaluator-optimizer (generator-critic) pattern.

One model generates a result and another model (or the same one with a different prompt) evaluates it against clear criteria and gives feedback. The generator revises, and the loop repeats until the result passes or a round limit is reached. It works well when quality can be judged clearly, for example code that must pass tests or a translation checked against a rubric.

Q12How does routing work, and why is it useful?

A router (a small LLM or a classifier) looks at the input and sends it to the best handler, for example billing vs technical support, or a cheap model for simple questions and a stronger model for hard ones. It improves quality through specialization and reduces cost by not using the most expensive path every time.

Q13When is parallelization useful, and what are sectioning and voting?
  • Sectioning: split a task into independent parts and run them at the same time, for example analyzing different sections of a long document.
  • Voting: run the same task several times (possibly with different prompts or models) and combine the answers, which gives higher confidence for important decisions.

Both reduce latency or improve reliability, at the price of more LLM calls.

Multi-agent systems

Q14Why use multiple agents instead of one?
  • Specialization: each agent has a focused role, prompt and toolset, which usually improves quality.
  • Smaller contexts: each agent sees only what it needs.
  • Parallel work: independent agents can run at the same time.
  • Separation of concerns: easier to test, replace and secure each part.

The trade-off is more cost, more coordination overhead and harder debugging, so start with one agent and split only when you have a clear reason.

Q15What are the common multi-agent architectures?
Architecture How it works Strength Risk
Sequential pipeline Agents run in a fixed order, each passing output on Simple, predictable Rigid, errors carry forward
Supervisor (hierarchical) A supervisor agent delegates to specialist agents and collects results Clear control The supervisor is a bottleneck
Network (peer-to-peer) Agents can talk to any other agent Flexible Hard to control and debug
Handoff / swarm An agent passes the conversation to a more suitable agent Natural for routing users Can bounce between agents
Debate / critic Agents argue or review each other’s work Better quality on hard problems Costly
Q16What is an agent handoff?

A handoff is when one agent transfers control of the task (and the relevant context) to another agent that is better suited to continue, for example a general support agent handing over to a billing agent. A good handoff passes a clear summary and the necessary state, so the next agent does not start from zero or ask the user again.

Q17How do agents communicate and share state?
  • Message passing: agents send structured messages to each other, directly or through a supervisor.
  • Shared state or memory: a common store (sometimes called a blackboard) that agents read from and write to.
  • Artifacts: agents pass files, code or documents as outputs for others to use.

Use structured formats (JSON schemas) instead of free text for messages, so receivers can validate them, and share only the context each agent needs.

Q18What are MCP and A2A, and how do they differ?
MCP (Model Context Protocol) A2A (Agent2Agent protocol)
Connects An agent or app to tools and data An agent to another agent
Purpose Standard way to expose tools, resources and prompts Standard way for agents, possibly from different vendors, to discover each other and collaborate on tasks
Analogy A USB port for tools A common language between agents

They are complementary: an agent can use MCP to call its tools, and A2A to delegate work to other agents.

Q19What challenges come with multi-agent systems?
  • Cost and latency: more LLM calls per task.
  • Coordination overhead: misunderstandings, duplicated work and endless back-and-forth between agents.
  • Error propagation: one agent’s mistake becomes another agent’s input.
  • Debugging: behavior emerges from interactions, so you need traces of every message.
  • Security: a compromised agent or message can affect the others.
  • Testing: more non-determinism than a single agent.
Q20How do you resolve conflicts or disagreements between agents?
  • Define clear roles and ownership so only one agent decides each thing.
  • Use a supervisor or arbiter agent for final decisions.
  • Use voting across several agents for important choices.
  • Set limits on the number of rounds and escalate to a human when agents cannot agree.

Orchestration and frameworks

Q21How do the popular frameworks approach multi-agent orchestration?
Framework Approach
LangGraph Agents as nodes in a graph with shared state; supports supervisor and hierarchical designs, checkpoints and human-in-the-loop
CrewAI Role-based “crews”: you define agents with roles and goals, assign them tasks and choose how they collaborate
AutoGen Agents that collaborate through conversations, including group chats
OpenAI Agents SDK Agents with explicit handoffs, guardrails and built-in tracing

Framework features change quickly, so check the current documentation before choosing one.

Q22What is a supervisor agent, and how would you design one?

A supervisor is an agent whose job is routing and coordination: it reads the request, decides which specialist agent should work on it, passes the context, checks the result and decides whether to continue, retry or finish.

Design tips: give it a short list of clear specialist descriptions, a structured way to choose the next agent (or “finish”), a step limit, and a way to ask a human when it is unsure.

Q23What is a shared state graph, and why is it useful?

In graph-based orchestration, every step (node) reads and updates a shared state object, and edges decide which node runs next, including conditional branches and loops. This makes the flow explicit, lets you checkpoint and resume, and makes it easier to see and test exactly how the system moved from input to output.

Q24Event-driven vs sequential orchestration: what is the difference?
  • Sequential or request-driven: one run follows one path from a user request to a result.
  • Event-driven: agents react to events (a new ticket, an alert, a file upload) and run asynchronously, often in the background, using queues or message brokers.

Event-driven designs suit long-running, automated work and scale well, but need stronger monitoring and idempotent actions.

Governance, safety and security

Q25What is “excessive agency”, and how do you prevent it?

Excessive agency is when an agent has more permissions, tools or autonomy than its task needs, so a mistake or an attack can cause serious damage (it is listed as a key risk in the OWASP guidance for LLM applications).

Prevent it with:

  • least-privilege tools and credentials,
  • narrow, specific tools instead of general ones,
  • approvals for high-impact actions,
  • limits on spending, rate and scope,
  • logging and the ability to roll back.
Q26What is the difference between human-in-the-loop and human-on-the-loop?
  • Human-in-the-loop: a person must approve or provide input at specific steps before the agent continues.
  • Human-on-the-loop: the agent acts on its own while a person monitors and can step in, pause or stop it.

Use in-the-loop for risky, irreversible actions, and on-the-loop for lower-risk, high-volume work with good monitoring.

Q27How should agents be given identity and permissions?

Treat each agent like a service account: give it its own identity, issue scoped, short-lived credentials, and apply role-based access so it can only reach the data and tools it needs. When an agent acts for a user, make sure it can never exceed that user’s own permissions, and log which agent did what on whose behalf.

Q28What are the main security threats to agentic systems?
  • Direct and indirect prompt injection: malicious instructions in user input or in content the agent reads.
  • Tool poisoning: a malicious or compromised tool or MCP server with misleading descriptions or harmful behavior.
  • Data leakage: an agent exposing sensitive data through its outputs or tool calls.
  • Privilege escalation through over-permissioned tools.
  • Agent-to-agent attacks: a compromised agent passing harmful instructions to others.
  • Supply-chain risk from third-party tools, models and plugins.
Q29How do you make agent actions auditable?

Log every run with a trace ID, the goal, each model call, each tool call with arguments and results, approvals and the final outcome. Store logs securely and keep them for the required period. This supports debugging, incident investigation, compliance reviews and accountability (who or what decided and acted).

Q30What is a kill switch or circuit breaker for agents?

It is a control that can stop or limit an agent quickly when something goes wrong: a manual stop, automatic limits on spending or number of actions, or a breaker that disables a tool after repeated failures or unusual behavior. Build it before you need it.

Q31What governance practices should an organization put in place for agentic AI?
  • A clear owner and accountability for each agent.
  • Risk-based autonomy levels with approval rules.
  • Review and testing before deployment, and continuous monitoring after.
  • Access control and data protection rules.
  • Audit logs and an incident-response plan.
  • Compliance with relevant regulations and internal policies.

Evaluation, production and use cases

Q32How do you evaluate an agentic system?
  • Outcome: task success rate on a representative test set.
  • Process: correct tool use, sensible plans, number of steps and unnecessary loops.
  • Multi-agent behavior: quality of handoffs, duplicated work and coordination cost.
  • Safety: policy violations, unauthorized actions and prompt-injection resistance.
  • Cost and latency per task.
  • Human feedback and review of failed runs.

Run each test several times, because outputs vary.

Q33How do you make agentic systems reliable in production?
  • Limits: step, time and cost budgets.
  • Retries with backoff and fallbacks (another tool, a simpler path, or a human).
  • Idempotent actions so retries do not repeat side effects.
  • Validation of inputs, outputs and tool arguments.
  • Checkpointing so long runs can resume.
  • Monitoring and alerting on success rate, cost and latency.
  • Gradual rollout with a human reviewing at first.
Q34What is agentic RAG?

In agentic RAG, retrieval is something an agent decides and controls: it chooses whether to search, which source to use, rewrites the query, checks whether the results are good enough and searches again if not, and can combine several sources. It handles complex and multi-step questions better than a fixed one-shot retrieval pipeline, at the cost of more steps and latency.

Q35What are computer-use and coding agents?
  • Computer-use (browser) agents operate software the way a person does: they look at the screen, click, type and navigate to complete tasks in applications that have no API.
  • Coding agents read a codebase, plan changes, edit files, run tests and fix failures.

Both are powerful but risky, so they need sandboxes, narrow permissions and review before changes are merged or actions are finalized.

Q36What are some enterprise use cases of agentic AI?
  • Customer support: resolving tickets, looking up orders, processing refunds within policy.
  • IT operations: triaging alerts and running routine fixes.
  • Software engineering: code generation, review and test fixing.
  • Finance and operations: invoice processing, reconciliation and report preparation.
  • Research and analysis: gathering, comparing and summarizing information.
  • Sales and marketing: lead research and personalized outreach drafts.
Q37How do you measure the business value (ROI) of an agentic AI project?

Compare against the process before the agent: time saved per task, tasks completed per person, cost per task, error and rework rate, response time and customer or employee satisfaction. Subtract the full cost of running it (model usage, infrastructure, monitoring, human review and maintenance). Start with a pilot on a well-defined process and measure with a control group.

Q38Design question: how would you build an agentic customer-support system?
  1. Scope and risk: decide which request types the system may handle (order status, returns) and which always go to a human (legal, large refunds).
  2. Architecture: a router classifies the request, then specialist agents (orders, billing, knowledge base) handle it, coordinated by a supervisor.
  3. Tools: read access to orders and a knowledge base through RAG, and write actions (refund, update address) only with scoped permissions and limits.
  4. Guardrails: policy checks, spending limits, approval for sensitive actions and protection against prompt injection from customer messages.
  5. Human handoff: escalate with a summary when confidence is low or the customer asks for a person.
  6. Evaluation: a test set of real tickets, success rate, escalation rate, safety checks and customer satisfaction.
  7. Operations: tracing, audit logs, cost and latency monitoring, and a gradual rollout.
Q39What are the current limitations and open challenges of agentic AI?
  • Reliability on long tasks, because small errors compound over many steps.
  • Cost and latency of multi-step runs.
  • Evaluation is harder than for single responses.
  • Security risks such as prompt injection and over-permissioned tools.
  • Trust and accountability when agents act autonomously.
  • Integration with legacy systems and messy real-world data.
