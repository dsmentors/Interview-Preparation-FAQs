What is the difference between “Primary Key” and “Unique Key”?
  1. A table can have only one Primary Key, but it can have more than one Unique Key.
  2. A Primary Key cannot have a NULL value, whereas a Unique Key may have a NULL value (only one NULL in SQL Server).
  3. By default, a Primary Key creates a clustered index, whereas a Unique Key creates a unique non-clustered index.
  4. A Primary Key supports an auto-increment value, whereas a Unique Key does not.
What are super, primary, candidate and foreign keys?
  • Super key: a set of attributes of a relation on which all other attributes depend. No two rows can have the same value for the super key attributes.
  • Candidate key: a minimal super key, meaning no proper subset of its attributes is a super key.
  • Primary key: the candidate key chosen as the most important one. A table cannot have more than one primary key.
  • Foreign key: a field (or collection of fields) in one table that refers to the primary key of another table.
What is Normalization?

Database normalization is a design process, based on a set of rules, for organizing data in a relational database so that redundancy is minimized. It usually means dividing a database into two or more tables and defining relationships between them, so that additions, deletions and modifications of a field can be made in just one table and then flow through the rest of the database via those relationships.

Relation schemas are analysed using their functional dependencies and primary keys to achieve two properties:

  1. Minimizing redundancy
  2. Minimizing insertion, deletion and update anomalies

Schemas that do not meet these properties are decomposed into smaller relation schemas that do.

What are the different types of normalization?

In database design we start with a single table holding all possible columns, which contains a lot of redundant data. Normalization removes that redundancy by splitting the table in a well-defined way.

  1. First Normal Form (1NF): all underlying domains contain atomic values only. After 1NF we can still have redundant data.
  2. Second Normal Form (2NF): the relation is in 1NF and every non-key attribute is fully dependent on the primary key. After 2NF we can still have redundant data.
  3. Third Normal Form (3NF): the relation is in 2NF and every non-key attribute is non-transitively dependent on the primary key.
What is De-normalization?

De-normalization is the process of optimizing the performance of a database by adding redundant data. It is sometimes necessary because current DBMSs implement the relational model imperfectly. A true relational DBMS would allow a fully normalized database at the logical level while providing physical storage tuned for high performance.

De-normalization is a technique to move from higher to lower normal forms of database modeling in order to speed up database access.

What is the difference between “Clustered Index” and “Non-Clustered Index”?

A clustered index decides how the data is physically stored on disk, so only one clustered index can exist per table. A non-clustered index does not define the physical order of the data, only a logical order. Typically a tree (B-Tree or B+ Tree) is built whose leaves point to the disk records.

What is a view in SQL? How to create one

A view is a virtual table based on the result set of an SQL statement. It is created with the CREATE VIEW syntax.

CREATE VIEW HighSalaryEmployees AS
SELECT FirstName, Salary
FROM EmployeeDetail
WHERE Salary > 600000;
What are the uses of views?
  1. A view can represent a subset of the data in a table, limiting how much of the underlying tables is exposed. A user may be allowed to query the view while being denied access to the base table.
  2. Views can join and simplify multiple tables into a single virtual table.
  3. Views can act as aggregated tables, where the database engine aggregates data (sum, average, etc.) and presents the calculated results.
  4. Views can hide the complexity of data. For example, a view can appear as Sales2000 or Sales2001 while transparently partitioning the actual underlying table.
  5. Depending on the SQL engine used, views can provide extra security.
What is a materialized view?

A materialized view is also a view, but it is disk based: the result is physically stored. It is refreshed at the interval specified in its definition, and it can be indexed.

What are the advantages and disadvantages of views in a database?

Advantages

  1. A view does not store data in a separate physical location.
  2. A view can hide some of the columns of a table.
  3. Views can provide access restriction, since inserting, updating and deleting data is not possible through certain views.

Disadvantages

  1. When a table is dropped, the associated view becomes irrelevant.
  2. A view is built when a query requests data from it, so it can be a bit slow.
  3. Views created over large tables occupy more memory.
What is a Trigger?

A trigger is code associated with INSERT, UPDATE or DELETE operations. It runs automatically whenever the associated query is executed on the table. Triggers are useful for maintaining integrity in the database.

What is a transaction? What are ACID properties?

A database transaction is a set of database operations that must be treated as a whole: either all operations are executed or none of them. A bank transfer is a good example, where both the debit and the credit must happen, or neither.

ACID (Atomicity, Consistency, Isolation, Durability) is the set of properties that guarantees database transactions are processed reliably.

  1. Atomicity: a transaction consists of many steps. If all steps complete, the result is reflected in the database; if any step fails, everything is rolled back.
  2. Consistency: the database moves from one consistent state to another if the transaction succeeds, and remains in the original state if it fails.
  3. Isolation: every transaction should operate as if it were the only transaction in the system.
  4. Durability: once a transaction has completed successfully, the updated rows/records must be available to all other transactions on a permanent basis.
What are indexes?

A database index is a data structure that improves the speed of data retrieval on a table, at the cost of additional writes and extra storage space for a copy of the data.

Data can be stored on disk in only one order. To search quickly on different values (for example with a binary search), indexes are created on the table. They need extra disk space, but they make searches on frequently used values much faster.

How do you implement one-to-one, one-to-many and many-to-many relationships while designing tables?
  • One-to-One: can be implemented as a single table, and rarely as two tables with a primary key and foreign key relationship.
  • One-to-Many: implemented by splitting the data into two tables with a primary key and foreign key relationship.
  • Many-to-Many: implemented using a junction table, with the keys from both tables forming the composite primary key of the junction table.
What is a Database Lock?

A database lock tells a transaction whether the data item in question is currently being used by other transactions.

What are the types of locks?
  1. Shared lock: while a shared lock is applied to a data item, other transactions can only read the item, but cannot write to it.
  2. Exclusive lock: while an exclusive lock is applied to a data item, other transactions can neither read nor write it.
What are wildcards used in a database for pattern matching?

The SQL LIKE operator is used for pattern matching.

Wildcard Meaning Example
% Any string of zero or more characters LIKE 'a%' finds names starting with a
_ Exactly one character LIKE '_a%' finds names with a as the second letter
[ ] Any single character in the set (SQL Server) LIKE '[abc]%'
[^ ] Any single character not in the set (SQL Server) LIKE '[^abc]%'

LIKE takes more time to process, so keep these suggestions in mind:

  1. Don't overuse wildcards. If another search operator will do, use it instead.
  2. When you do use wildcards, try not to put them at the beginning of the search pattern unless absolutely necessary. Patterns that begin with a wildcard are the slowest to process.
  3. Pay careful attention to the placement of the wildcard symbols. If they are misplaced, you might not return the data you intended.
Define Join and explain the different types of joins

To avoid data duplication, data is stored in related tables. The JOIN keyword is used to fetch data from related tables.

  • Inner join: returns rows when there is at least one match in both tables.
  • Left (outer) join: returns all rows from the left table, even if there are no matches in the right table.
  • Right (outer) join: returns all rows from the right table, even if there are no matches in the left table.
  • Full (outer) join: returns all rows when there is a match in either of the tables.
What is a Self-Join?

A self-join is a query that joins a table to itself. Aliases must be used to distinguish the two copies of the same table when comparing them.

What is a Cross Join?

A cross join returns every combination of rows: each row of the first table is combined with each row of the second table.

Q22How to find the Nth maximum salary?

Oracle syntax (&N is a substitution variable, so you are asked for the value of N):

SELECT DISTINCT SAL
FROM EMP A
WHERE &N = (SELECT COUNT(DISTINCT B.SAL) FROM EMP B WHERE A.SAL <= B.SAL);

Another way, using DENSE_RANK (here N = 3):

SELECT DISTINCT Salary
FROM (SELECT Salary, DENSE_RANK() OVER (ORDER BY Salary DESC) AS rnk
      FROM EmployeeDetail) T
WHERE rnk = 3;
Q23How to use the EXISTS clause?

EXISTS returns true when the sub-query returns at least one row. This query lists only the departments that have employees:

SELECT DNAME, DEPTNO
FROM DEPT
WHERE EXISTS (SELECT * FROM EMP WHERE DEPT.DEPTNO = EMP.DEPTNO);
Q24How to delete the duplicate rows alone in a table?

Oracle syntax (uses ROWID). It keeps one row per DEPTNO and deletes the rest:

DELETE DEPT
WHERE ROWID NOT IN (SELECT MAX(ROWID) FROM DEPT GROUP BY DEPTNO HAVING COUNT(*) >= 1);
Q25How to find the max salary without using the MAX function?
SELECT DISTINCT SAL
FROM EMP1
WHERE SAL NOT IN (SELECT SAL FROM EMP1
                  WHERE SAL < ANY (SELECT SAL FROM EMP1));

The inner query returns every salary that has a bigger salary above it, so what is left after NOT IN is the highest salary.

Q26How can I eliminate duplicate values in a table?

Oracle syntax (uses ROWID). It keeps the row with the smallest ROWID for each set of key values:

DELETE FROM table_name A
WHERE ROWID > (SELECT MIN(ROWID) FROM table_name B
               WHERE A.key_values = B.key_values);

Q30FuelDetail table (ID, Fuel, Date): find out when the driver filled petrol in the car

The Fuel column holds the fuel quantity at a particular time while the car is travelling (see the table image at the top of this section). An example:

  • The car starts driving at 10 AM on 25 April with 10 litres of petrol.
  • At 11 AM there are 9 litres, and at 12 PM there are 8 litres.
  • At 2 PM (14:00) there are 12 litres, which means the driver filled petrol at 2 PM on 25 April 2014.
  • The next fill-ups were at 7 PM and 11 PM on 25 April 2014.
SELECT c1.Fuel AS [Fuel quantity Now],    c1.[Date] AS [Refill time],
       c.Fuel  AS [Fuel quantity Before], c.[Date]  AS [Previous reading]
FROM FuelDetail c
JOIN FuelDetail c1
  ON c1.[Date] = (SELECT MIN([Date]) FROM FuelDetail WHERE [Date] > c.[Date])
WHERE c1.Fuel > c.Fuel;

Each row c is joined with the next reading in time (c1). If the fuel went up between the two readings, the driver filled petrol.

Q1Write a query to get the top 4 highest selling states

Joins the Sales table to the Store table to get each store's state, then adds up the dollars per state.

SELECT TOP 4 st.State, SUM(s.Dollars) AS Total_Dollars
FROM Sales s
JOIN Store st ON s.[Store #] = st.[Store #]
GROUP BY st.State
ORDER BY Total_Dollars DESC;

“Highest selling” is measured here by dollars. Use SUM(s.Units) if it should be by units.

Q2Print the number of stores having sales less than 50 in each week for the year 2021

First add up each store's sales per week, keep the store-weeks under 50, then count the stores for every week.

SELECT Week, COUNT(*) AS Stores_Below_50
FROM (SELECT Week, [Store #], SUM(Dollars) AS Week_Dollars
      FROM Sales
      WHERE Year = 2021
      GROUP BY Week, [Store #]
      HAVING SUM(Dollars) < 50) T
GROUP BY Week
ORDER BY Week;
Q3Write a query to get Store, Store Name, SKU, Category, and the total dollars and average units for each
SELECT s.[Store #], st.[Store Name], s.SKU, k.Category,
       SUM(s.Dollars) AS Total_Dollars,
       AVG(CAST(s.Units AS DECIMAL(10, 2))) AS Avg_Units
FROM Sales s
JOIN Store st ON s.[Store #] = st.[Store #]
JOIN SKU k ON s.SKU = k.SKU
GROUP BY s.[Store #], st.[Store Name], s.SKU, k.Category;

The SKU table is shown as an image, so the query assumes it has SKU and Category columns. Adjust the names to match your table. The CAST stops SQL Server from rounding the average down to a whole number.

Q5Suppose we have 2 tables with 10 rows each. What will be the maximum and minimum number of rows we get after joining these two tables?

It depends on the type of join:

Join type Minimum rows Maximum rows
INNER JOIN 0 100
LEFT JOIN 10 100
RIGHT JOIN 10 100
FULL OUTER JOIN 10 100
CROSS JOIN 100 100
  • The maximum is 10 × 10 = 100, when every row of one table matches every row of the other (for example all join keys are the same).
  • An inner join returns 0 rows when no keys match.
  • A left or right join always keeps every row of the preserved table, so the minimum is 10.
  • A full outer join returns 10 rows when the rows pair up one-to-one, 20 when nothing matches, and 100 when everything matches.
  • A cross join has no join condition, so it always returns exactly 100 rows.
Q6Write a query to get the total number of units and sales (Sales table) of each store (pull only the top 10) in the year 2020

“Top 10” is ranked by sales here. Change the ORDER BY to Total_Units to rank by units.

Q7What is the order of execution in an SQL query?

SQL does not run a query in the order it is written. The logical order is:

  1. FROM (including JOINs)
  2. WHERE
  3. GROUP BY
  4. HAVING
  5. SELECT (expressions and aliases are computed here)
  6. DISTINCT
  7. ORDER BY
  8. TOP / LIMIT / OFFSET

This is why a column alias defined in SELECT cannot be used in WHERE, but it can be used in ORDER BY.
