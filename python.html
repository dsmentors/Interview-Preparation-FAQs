Immutable data types cannot be changed after creation (e.g. strings, tuples, numbers).

What is a decorator?

A decorator is a function that modifies the behavior of another function. It wraps the original function to extend its behavior without permanently modifying it.

def log_call(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@log_call

    return f"Hello, {name}!"

print(greet("Alice"))
# Calling greet
# Hello, Alice!

What is an exception in Python? How do you handle exceptions?

An exception is an error that occurs during program execution. The try, except and finally blocks are used to handle exceptions.

  • try: contains the code that might raise an exception.
  • except: runs only if an exception occurs in the try block.
  • else (optional): runs only if no exception occurs.
  • finally: always runs, whether or not an exception occurred.
try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")
else:
    print(result)
finally:
    print("Done")
# Cannot divide by zero
# Done
What is raise in Python?

The raise statement is used to manually trigger an exception. It is useful when you want to signal that an error or exceptional condition has occurred in your program.

By raising an exception, you transfer control to exception handling code, which can manage or respond to the error appropriately.

Syntax:

raise ExceptionType("message")

Example:

def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("Division by zero is not allowed.")
    return a / b

try:
    result = divide(10, 0)
except ZeroDivisionError as e:
    print(e)  # Output: Division by zero is not allowed.
What is a custom exception?

A custom exception is an exception you create yourself by defining a new class that inherits from Python's built-in Exception class (or one of its subclasses). Custom exceptions let you define specific error conditions in your code and raise them when needed.

Example:

# Define a custom exception
class CustomError(Exception):
    pass

# Function that raises the custom exception
def check_value(value):
    if value < 0:
        raise CustomError("Value cannot be negative.")
    return value

try:
    check_value(-1)
except CustomError as e:
    print("Caught a custom exception:", e)
# Output: Caught a custom exception: Value cannot be negative.

What is the Global Interpreter Lock (GIL) in Python?

The Global Interpreter Lock (GIL) is a mutex (mutual exclusion lock) that protects access to Python objects, preventing multiple threads from executing Python bytecode at the same time in a multi-threaded program. The lock is needed because CPython's memory management is not thread-safe.

The GIL ensures that only one thread executes in the Python interpreter at any one time. This simplifies memory management and garbage collection, but it also limits the concurrency of CPU-bound Python programs.

What is a recursive function in Python? Give an example.

A recursive function is a function that calls itself. It needs a base case to stop the recursion. Here is a recursive function that calculates the factorial of a number:

def factorial(n):
    if n == 0:        # base case
        return 1
    else:
        return n * factorial(n - 1)

print(factorial(5))  # Output: 120

What is the difference between methods and functions?

Functions

A function is a block of reusable code that performs a specific task, defined using the def keyword. Functions can be defined at global scope, inside modules, or inside other functions (nested functions).

  • They are not inherently associated with any object or class.
  • They are called by name followed by parentheses, optionally passing arguments.

Example:

def greet(name):
    return f"Hello, {name}!"

print(greet("Alice"))  # Output: Hello, Alice!

Methods

A method is a function that is associated with an object and defined inside a class. Methods operate on the data contained in the objects of that class. They are called on an object using dot notation, and the object instance is passed implicitly as the first argument, conventionally named self.

Example:

class Greeter:
    def __init__(self, name):
        self.name = name

    def greet(self):
        return f"Hello, {self.name}!"

greeter = Greeter("Alice")
print(greeter.greet())  # Output: Hello, Alice!
What is slicing in Python?

Slicing is a technique used to extract a portion of a sequence such as a list, tuple or string. It uses the colon : operator inside square brackets: sequence[start:stop:step].

  • start: the starting index of the slice (inclusive). Defaults to 0.
  • stop: the ending index of the slice (exclusive), so the slice includes elements up to, but not including, this index. Defaults to the length of the sequence.
  • step: the step size, i.e. how many elements to skip. Defaults to 1.

Example:

my_list = [0, 1, 2, 3, 4, 5]
print(my_list[:3])   # Output: [0, 1, 2]
print(my_list[3:])   # Output: [3, 4, 5]
print(my_list[::2])  # Output: [0, 2, 4]
Explain the *args and **kwargs syntax in Python.

*args passes a variable number of non-keyword arguments to a function. They are collected into a tuple inside the function.

**kwargs passes a variable number of keyword arguments to a function. They are collected into a dictionary inside the function.

Example: *args

def my_function(*args):
    for arg in args:
        print(arg)

my_function(1, 2, 3, "hello")  # Output: 1 2 3 hello (one per line)

Example: **kwargs

def my_function(**kwargs):
    for key, value in kwargs.items():
        print(f"{key}: {value}")

my_function(name="Alice", age=30, city="New York")
# name: Alice
# age: 30
# city: New York

What is the difference between map, filter and reduce in Python?
  • map applies a given function to each item of an iterable and returns an iterator.
  • filter keeps the items of an iterable for which a given function returns true, and returns an iterator.
  • reduce applies a function cumulatively to the items of an iterable and reduces it to a single value. It must be imported from functools.
from functools import reduce

nums = [1, 2, 3, 4]
print(list(map(lambda x: x * 2, nums)))         # [2, 4, 6, 8]
print(list(filter(lambda x: x % 2 == 0, nums)))  # [2, 4]
print(reduce(lambda a, b: a + b, nums))          # 10
Explain method overriding and provide an example.

Method overriding occurs when a subclass provides its own implementation of a method that is already defined in its parent class.

Key points:

  • Overriding allows customization of inherited behavior.
  • The version of the method that runs depends on the type of the object.
  • The overriding method should keep the same name and parameters as the parent method.

Example:

class Animal:
    def make_sound(self):
        print("Generic animal sound")

class Dog(Animal):
    def make_sound(self):
        print("Woof!")

class Cat(Animal):
    def make_sound(self):
        print("Meow!")

# Create objects
animal = Animal()
dog = Dog()
cat = Cat()

# Call make_sound on different objects
animal.make_sound()  # Output: Generic animal sound
dog.make_sound()     # Output: Woof!
cat.make_sound()     # Output: Meow!
  • The Animal class defines a general make_sound method.
  • The Dog and Cat classes override make_sound to provide their own sounds.
  • When we call make_sound on each object, the overridden version for that object's type is executed.

What is an iterator?

An iterator is an object that implements the iterator protocol, which consists of two methods:

  • __iter__(): returns the iterator object itself.
  • __next__(): returns the next item in the sequence, and raises StopIteration when there are no more items.

Iterators are used to traverse iterable objects such as lists, tuples and strings. They are created using the iter() function.

my_list = [1, 2, 3]
my_iter = iter(my_list)
print(next(my_iter))  # Output: 1
print(next(my_iter))  # Output: 2
What is a generator?

A generator is a special type of iterator created using a function with the yield keyword. Calling a generator function returns a generator object without running the function body immediately.

Execution pauses at each yield statement, saving its state and returning the yielded value. The next time next() is called, the function resumes from where it left off.

def my_generator():
    for i in range(5):
        yield i

my_gen = my_generator()
print(next(my_gen))  # Output: 0
print(next(my_gen))  # Output: 1

Can you explain the zip concept in Python?

The built-in zip function combines two or more iterables (e.g. lists, tuples) into a single iterator of tuples. Each tuple contains the elements from each iterable at the same index, so it "zips" the iterables together element by element.

Key points:

  • zip takes multiple iterables and combines them element-wise into tuples.
  • The result is as long as the shortest input iterable. If the iterables have different lengths, it stops at the end of the shortest one.
  • It returns an iterator of tuples. To get a list of tuples, pass the result to list().
list1 = [1, 2, 3, 4]
list2 = ['a', 'b', 'c']
zipped = zip(list1, list2)
print(list(zipped))  # Output: [(1, 'a'), (2, 'b'), (3, 'c')]
Can you explain the concept of concurrency in Python?

Concurrency is the ability of a program to handle multiple tasks at the same time, or at least give the appearance of doing so. Python supports it in three main ways, each with its own use cases, advantages and limitations:

  • Threading: multiple threads run inside a single process and share memory (threading module). Best for I/O-bound tasks such as network calls or file reads. Because of the GIL, threads do not run Python code in parallel, so it does not speed up CPU-bound work.
  • Multiprocessing: multiple processes run independently, each with its own memory and its own interpreter (multiprocessing module). Gives true parallelism across CPU cores, so it suits CPU-bound tasks.
  • Asynchronous programming: a single thread runs an event loop that switches between tasks while they wait, using async/await (asyncio module). Best for handling many I/O-bound tasks efficiently, such as thousands of network requests.
What is the difference between multiprocessing and multithreading?

Multiprocessing uses multiple processes to perform tasks concurrently. Each process runs independently and has its own memory space. Tasks can run in parallel on multiple CPU cores, which suits CPU-bound tasks.

Key points:

  • Independent processes
  • True parallelism
  • No GIL limitation
  • Inter-process communication (IPC) needed to share data

Multithreading uses multiple threads within a single process. Threads share the memory space and resources of the process, which makes communication between them easier and more efficient.

Key points:

  • Shared memory space
  • Concurrency but limited parallelism
  • Simpler communication
  • Lightweight

Can you describe object-oriented programming and its concepts?

Object-oriented programming (OOP) is a programming paradigm built around objects, which are instances of classes. The key concepts are:

  • Class: a blueprint or template for creating objects. It defines the properties (attributes) and behaviors (methods) that objects of the class have.
  • Object: an instance of a class. Objects are created from the structure defined by the class and can interact with each other to perform tasks.
  • Encapsulation: bundling data (attributes) and the methods that operate on it into a single unit (the class). It hides the internal state and requires interaction to go through the object's methods.
  • Inheritance: the mechanism by which one class inherits properties and behaviors from another. The class being inherited from is the base class or superclass, and the class inheriting is the derived class or subclass. Inheritance promotes code reuse and allows hierarchical relationships between classes.
  • Polymorphism: the ability of different objects to respond in their own way to the same method call. Methods can be written to handle objects of a certain class and also work with its subclasses, which can override or extend the superclass behavior.
  • Abstraction: hiding complex implementation details and showing only the essential features of an object. It reduces complexity and improves understandability.
What is the difference between multiple inheritance and multilevel inheritance?

Both are ways to build relationships between classes, but they differ in structure and in how classes inherit from each other.

Multiple inheritance

  • Definition: a class inherits attributes and methods from more than one parent class.
  • Example: given classes A and B, a third class C can inherit from both A and B at the same time.
  • Usage: useful when a class needs behaviors and attributes from several sources. It can lead to complexity and ambiguity known as the diamond problem, when two parent classes share a common ancestor. Python resolves this using the method resolution order (MRO).
class A:
    pass

class B:
    pass

class C(A, B):  # multiple inheritance
    pass

Multilevel inheritance

  • Definition: a chain of inheritance where a derived class serves as the base class for another class, forming a hierarchy.
  • Example: class A is inherited by class B, and class B is inherited by class C.
  • Usage: sets up a parent-child relationship where each subclass inherits attributes and methods from its immediate superclass.
class A:
    pass

class B(A):
    pass

class C(B):  # multilevel inheritance
    pass

Key differences

  • Structure: multiple inheritance inherits from several classes at the same level, whereas multilevel inheritance is a chain in which each subclass inherits from its immediate superclass.
  • Complexity: multiple inheritance can lead to the diamond problem. Multilevel inheritance is a linear hierarchy, so it is simpler to structure and manage.
  • Usage: multiple inheritance is used when a class needs several sources at once, while multilevel inheritance builds a hierarchy where each subclass adds more specific behavior.

How does Python manage memory, and what is garbage collection?

Python manages memory automatically in a private heap:

  • Reference counting: every object keeps a count of how many names or containers refer to it. When the count drops to zero, the memory is freed immediately.
  • Cyclic garbage collector: reference counting cannot free objects that refer to each other in a cycle (a refers to b and b refers to a). The gc module detects and removes such unreachable cycles periodically.
  • Weak references (weakref) refer to an object without increasing its reference count.
import sys
import gc

a = []
b = a
print(sys.getrefcount(a))     # 3: a, b and the temporary argument of getrefcount
del b
print(sys.getrefcount(a))     # 2
print(gc.collect())           # runs the cyclic collector, returns the number of objects found
What is the difference between a shallow copy and a deep copy?
  • A shallow copy (copy.copy, list.copy(), slicing) creates a new outer object, but the inner objects are shared with the original.
  • A deep copy (copy.deepcopy) recursively copies everything, so the copy is fully independent.
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

original[0].append(99)
print(shallow[0])      # [1, 2, 99]  the inner list is shared
print(deep[0])         # [1, 2]      independent copy

A plain assignment (b = a) does not copy anything: both names point to the same object.

How are arguments passed in Python? What is the mutable default argument pitfall?

Python passes references to objects (“pass by object reference”). If a function changes a mutable object it received (a list or dict), the caller sees the change. Reassigning the parameter name does not affect the caller.

Pitfall: default values are created once, when the function is defined, so a mutable default is shared between calls.

def add_item(item, items=[]):          # bug: one shared list
    items.append(item)
    return items

print(add_item(1))                      # [1]
print(add_item(2))                      # [1, 2]  surprising

def add_item_safe(item, items=None):    # correct pattern
    if items is None:
        items = []
    items.append(item)
    return items

print(add_item_safe(1), add_item_safe(2))   # [1] [2]
What are variable scopes in Python (LEGB), and what do global and nonlocal do?

Python looks up a name in this order, called LEGB: Local (inside the function), Enclosing (outer functions), Global (the module), Built-in.

  • global x lets a function assign to the module-level variable x.
  • nonlocal x lets an inner function assign to the variable of the enclosing function.
x = "global"

def outer():
    x = "enclosing"

    def inner():
        nonlocal x
        x = "changed by inner"

    inner()
    return x

print(outer())      # changed by inner
print(x)            # global

Reading a variable from an outer scope works without any keyword. The keywords are only needed to assign.

What is a closure, and what is the late-binding gotcha?

A closure is an inner function that remembers the variables of the function that created it, even after that function has finished.

def make_multiplier(n):
    def multiply(x):
        return x * n                 # n is remembered
    return multiply

double = make_multiplier(2)
print(double(5))                     # 10

Late binding: closures look up the variable when they are called, not when they are defined.

funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])          # [2, 2, 2]

funcs = [lambda i=i: i for i in range(3)]       # bind the current value with a default argument
print([f() for f in funcs])          # [0, 1, 2]
How do you write a decorator that takes arguments and keeps the function’s metadata?

A decorator with arguments is a function that returns a decorator. Use functools.wraps so the wrapped function keeps its __name__ and docstring.

import functools

def retry(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == times - 1:
                        raise            # give up after the last attempt
        return wrapper
    return decorator

calls = {"n": 0}

@retry(times=3)
def flaky():
    """Fails twice, then works."""
    calls["n"] += 1
    if calls["n"] < 3:
        raise ValueError("not yet")
    return "ok"

print(flaky(), calls["n"], flaky.__name__)      # ok 3 flaky
What is a context manager, and how do you create one?

A context manager sets something up and always cleans it up (even if an error occurs), and is used with the with statement: files, locks, database connections.

Class-based (__enter__ and __exit__):

import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        return False                    # False means: do not suppress exceptions

with Timer() as t:
    sum(range(100000))
print(t.elapsed > 0)                    # True

Generator-based with contextlib:

from contextlib import contextmanager

@contextmanager
def opened(path, mode="r"):
    f = open(path, mode)
    try:
        yield f                         # the body of the with block runs here
    finally:
        f.close()
What are yield from and generator expressions? How do they save memory?
  • yield from hands over to another iterable and yields all its items, which makes it easy to chain generators.
  • A generator expression (x for x in ...) is a lazy version of a list comprehension: it produces one value at a time instead of building the whole list in memory.
def chain(*iterables):
    for it in iterables:
        yield from it

print(list(chain([1, 2], (3, 4), "ab")))      # [1, 2, 3, 4, 'a', 'b']

squares = (x * x for x in range(1_000_000))   # nothing is computed yet
print(sum(squares))                            # processes one value at a time, O(1) memory

A generator can be consumed only once.

How does sorting work in Python (sorted, list.sort, key, stability)?

def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

power_of_two = partial(pow, 2)                # fix the first argument
print(power_of_two(10))                       # 1024
print(fib(50))                                # 12586269025

print(list(combinations([1, 2, 3], 2)))       # [(1, 2), (1, 3), (2, 3)]
print(len(list(permutations([1, 2, 3]))))     # 6
print(list(accumulate([1, 2, 3, 4])))         # [1, 3, 6, 10]

groupby groups consecutive items with the same key (sort first if needed), and functools.wraps and cached_property are also commonly used.

What are type hints, and does Python enforce them?

Type hints document the expected types of arguments and return values. Python does not enforce them at run time, but tools such as mypy and your IDE use them to catch bugs, and they make the code easier to read.

from typing import Optional

def greet(name: str, times: int = 1) -> str:
    return ("Hello " + name + "! ") * times

def find(items: list[int], target: int) -> Optional[int]:    # list[int] needs Python 3.9+
    for i, x in enumerate(items):
        if x == target:
            return i
    return None

Common helpers: Optional, Union (or int | None in Python 3.10+), list[str], dict[str, int], Callable and TypedDict.

What is the difference between else and finally in a try block? What are EAFP and LBYL?
  • else runs only if no exception occurred in the try block.
  • finally always runs (cleanup), whether or not an exception happened.
def read_number(text):
    try:
        value = int(text)
    except ValueError:
        print("not a number")
        return None
    else:
        print("parsed fine")
        return value
    finally:
        print("done")             # always printed
  • EAFP (“Easier to Ask Forgiveness than Permission”): try the operation and handle the exception. This is the Pythonic style.
  • LBYL (“Look Before You Leap”): check conditions first (if key in d:).

Use raise NewError(...) from original to keep the original error as the cause.

What is asyncio, and how is async/await different from threads?

asyncio runs many I/O-bound tasks concurrently in a single thread, using an event loop. A coroutine (async def) gives control back to the loop at each await, so while one task waits (network, disk), others can run.

import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)              # stands in for a network call
    return f"{name} done"

async def main():
    results = await asyncio.gather(fetch("a", 0.2), fetch("b", 0.1))
    print(results)                          # ['a done', 'b done'], after about 0.2 s in total

asyncio.run(main())

Use asyncio for many network-bound tasks, threads for blocking I/O libraries, and multiprocessing for CPU-bound work. A blocking call inside a coroutine freezes the whole event loop.

How do you make Python code faster?

First measure, then optimize the real bottleneck (timeit, cProfile, line profilers).

  • Choose better algorithms and data structures (a set or dict for lookups instead of scanning a list).
  • Use built-ins and the standard library (sum, sorted, str.join), which are implemented in C.
  • Use NumPy and pandas vectorization instead of Python loops.
  • Use generators to avoid building large lists.
  • Cache repeated results with functools.lru_cache.
  • Build strings with "".join(parts) instead of += in a loop.
  • For heavy CPU work: multiprocessing, Cython, Numba, or a faster language for the hot path.
import timeit

How do regular expressions work in Python?

The re module searches and manipulates text with patterns.

import re

text = "Order 123 shipped on 2024-05-17"
print(re.findall(r"\d+", text))                   # ['123', '2024', '05', '17']

m = re.search(r"(\d{4})-(\d{2})-(\d{2})", text)

How do Python dictionaries work internally?

A dict is a hash table: the key’s hash decides where the entry is stored, which gives O(1) average lookup, insert and delete.

  • Keys must be hashable (immutable): strings, numbers and tuples (of hashable items) are fine, lists and dicts are not.
  • Since Python 3.7, a dict remembers insertion order.
  • Useful methods: get(key, default), setdefault, items(), pop, and the merge operator d1 | d2 (3.9+).
d = {"a": 1}
d.setdefault("b", 2)
merged = d | {"c": 3}
print(merged)                       # {'a': 1, 'b': 2, 'c': 3}
print(d.get("z", "missing"))        # missing
How does Python run your code (CPython, bytecode, dynamic typing)?

Python source is compiled to bytecode (stored in .pyc files) and then executed by the Python virtual machine inside the interpreter. The standard implementation is CPython (written in C). Python is dynamically typed (types belong to values, and names can be rebound to any type) and strongly typed (it does not silently convert unrelated types, so "1" + 1 raises an error).

What are truthy and falsy values, and how do any() and all() work?

Falsy values are False, None, 0, 0.0, empty collections ("", [], {}, (), set()) and objects whose __bool__ returns False. Everything else is truthy.

  • any(iterable) is True if at least one item is truthy.
  • all(iterable) is True if every item is truthy (and True for an empty iterable).
print(bool([]), bool([0]))                    # False True
print(any(x > 3 for x in [1, 2, 5]))          # True
print(all(x > 0 for x in [1, 2, 5]))          # True

Object-oriented programming in Python

What is a class, and what is an object?

A class is a blueprint that defines the data (attributes) and behavior (methods) of something. An object (instance) is a concrete thing created from that class.

class Dog:
    species = "Canis familiaris"            # class attribute, shared

    def __init__(self, name, age):
        self.name = name                    # instance attributes
        self.age = age

    def bark(self):
        return f"{self.name} says woof"

rex = Dog("Rex", 3)                         # an object
print(rex.bark())                           # Rex says woof
What are __init__ and self?
  • __init__ is the initializer: Python calls it automatically right after an object is created, to set up its attributes.
  • self is the instance the method is working on. It is the first parameter of every instance method, and Python passes it automatically (rex.bark() is the same as Dog.bark(rex)). The name self is a convention, not a keyword.
What is the difference between instance attributes and class attributes?
  • Instance attributes (set with self.x = ...) belong to one object.
  • Class attributes (defined in the class body) are shared by all instances.
class Counter:
    count = 0                       # class attribute

    def __init__(self):
        Counter.count += 1          # change the shared value through the class

a, b = Counter(), Counter()
print(Counter.count, a.count)       # 2 2

Pitfall: a mutable class attribute (such as a list) is shared by every instance, so changing it in one object changes it in all.

What are instance methods, class methods and static methods?
Type First parameter Can access Typical use
Instance method self The instance and the class Normal behavior
Class method (@classmethod) cls The class, not a specific instance Alternative constructors, class-level state
Static method (@staticmethod) none Neither A utility function that belongs with the class 
class Date:
    def __init__(self, y, m, d):
        self.y, self.m, self.d = y, m, d

    @classmethod
    def from_string(cls, s):                 # alternative constructor
        y, m, d = map(int, s.split("-"))
        return cls(y, m, d)

    @staticmethod
    def is_leap(year):
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

d = Date.from_string("2024-05-17")
print(d.y, Date.is_leap(2024))              # 2024 True
How is encapsulation implemented in Python? (public, protected, private)

Encapsulation means bundling data with the methods that use it and controlling access to it. Python relies on naming conventions, not strict access control:

  • name is public.
  • _name is protected by convention (“internal use, please do not touch”).
  • __name triggers name mangling: Python renames it to _ClassName__name, which avoids accidental overrides in subclasses (it is not real security).
class Account:
    def __init__(self, balance):
        self.__balance = balance            # becomes _Account__balance

    def deposit(self, amount):
        self.__balance += amount

acc = Account(100)
acc.deposit(50)
print(acc._Account__balance)                # 150  still reachable, but discouraged
What is the @property decorator, and why use it?

@property lets you access a method like an attribute, so you can add validation or computed values without changing how the class is used.

class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius               # goes through the setter below

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("below absolute zero")
        self._celsius = value

    @property
    def fahrenheit(self):                    # read-only computed attribute
        return self._celsius * 9 / 5 + 32

t = Temperature(25)
print(t.fahrenheit)                          # 77.0
How does inheritance work, and what does super() do?

A subclass inherits the attributes and methods of its parent, can add new ones and override existing ones. super() gives access to the parent class, typically to run its __init__ or to extend a method.

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)               # initialize the parent part
        self.breed = breed

    def speak(self):
        return "Woof"

d = Dog("Rex", "Labrador")
print(d.name, d.speak(), isinstance(d, Animal))      # Rex Woof True
What is the MRO (Method Resolution Order), and what is the diamond problem?

With multiple inheritance, Python must decide which parent’s method to use. The MRO is the order in which classes are searched, computed with the C3 linearization, and you can see it with ClassName.__mro__ or help().

The diamond problem is when a class inherits from two classes that share a common base. Python handles it by ensuring each class appears once, after all its subclasses.

class A:
    def who(self): return "A"

class B(A):
    def who(self): return "B"

class C(A):
    def who(self): return "C"

class D(B, C):
    pass

print([cls.__name__ for cls in D.__mro__])     # ['D', 'B', 'C', 'A', 'object']
print(D().who())                               # B

Using super() consistently in every class lets the cooperative calls follow the MRO.

What is polymorphism and duck typing?

Polymorphism means the same interface can work with different types. In Python this is often achieved through duck typing: “if it walks like a duck and quacks like a duck, it is a duck”. The code cares about what an object can do, not about its class.

class Duck:
    def speak(self): return "Quack"

class Robot:
    def speak(self): return "Beep"

def make_it_speak(thing):
    return thing.speak()                 # works for any object that has speak()

print(make_it_speak(Duck()), make_it_speak(Robot()))     # Quack Beep
How do you implement abstraction with abstract base classes (ABC)?

Abstraction means exposing what something does and hiding how. The abc module lets you define a class with abstract methods that every subclass must implement, and you cannot create an object from the abstract class itself.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        ...

class Circle(Shape):
    def __init__(self, r):
        self.r = r

    def area(self):
        return 3.14159 * self.r ** 2

print(round(Circle(2).area(), 2))        # 12.57
# Shape()  ->  TypeError: Can't instantiate abstract class
What are dunder (magic) methods? What is the difference between __str__ and __repr__?

Dunder methods (double underscore) let your objects work with Python’s built-in syntax and functions: __init__, __len__, __getitem__, __iter__, __call__, __eq__, __add__, __enter__/__exit__ and more.

  • __str__ gives a readable string for users (print(obj), str(obj)).
  • __repr__ gives an unambiguous string for developers (debugging, the REPL), ideally one that could recreate the object.
class Book:
    def __init__(self, title):
        self.title = title

    def __repr__(self):
        return f"Book(title={self.title!r})"

    def __str__(self):
        return self.title

    def __len__(self):
        return len(self.title)

b = Book("Dune")
print(str(b), repr(b), len(b))          # Dune Book(title='Dune') 4

If only one is defined, define __repr__.

What is operator overloading? Show an example.

Operator overloading means defining how operators (+, ==, <, []) behave for your own classes, by implementing the matching dunder methods.

class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

print(Vector(1, 2) + Vector(3, 4))               # Vector(4, 6)
print(Vector(1, 2) == Vector(1, 2))              # True
What is the relationship between __eq__ and __hash__?

Objects used in sets or as dict keys need a hash. The rule: objects that compare equal must have the same hash. If you define __eq__ in a class, Python removes the default __hash__ (the object becomes unhashable), so you must define __hash__ too if you want to use it in sets or as a key. Hash only immutable fields, because a changing hash would break the set or dict.

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):
        return hash((self.x, self.y))

print(len({Point(1, 2), Point(1, 2)}))        # 1
Composition vs inheritance: when do you use each?
  • Inheritance models an “is-a” relationship (a Dog is an Animal).
  • Composition models a “has-a” relationship (a Car has an Engine): one object holds another and delegates work to it.

A common guideline is “favor composition over inheritance”. Deep inheritance trees are rigid and tightly coupled, while composed objects are easier to change, test and reuse.

class Engine:
    def start(self):
        return "engine started"

class Car:
    def __init__(self):
        self.engine = Engine()            # composition

    def start(self):
        return self.engine.start()

print(Car().start())                      # engine started
What is the difference between __new__ and __init__? How do you build a singleton?
  • __new__ creates the object (it returns the new instance). It is rarely overridden.
  • __init__ initializes the object after it has been created.

Overriding __new__ is one way to implement a singleton (a class with only one instance):

class Singleton:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

print(Singleton() is Singleton())          # True

In Python, a module-level object is often a simpler singleton.

What is a metaclass?

In Python, classes are objects too, and a metaclass is the “class of a class”: it controls how classes are created. The default metaclass is type, so type(MyClass) is type.

class Meta(type):
    def __new__(mcs, name, bases, attrs):
        attrs["created_by"] = "Meta"             # add something to every class using this metaclass
        return super().__new__(mcs, name, bases, attrs)

class Thing(metaclass=Meta):
    pass

print(Thing.created_by)                          # Meta
print(type(Thing).__name__)                      # Meta

Metaclasses are used by frameworks (ORMs, abstract base classes) and are rarely needed in everyday code. If you only need to customize a class, a class decorator or __init_subclass__ is usually simpler.

What are dataclasses, and why use them?

@dataclass generates boilerplate (__init__, __repr__, __eq__, and optionally ordering and hashing) from annotated fields, which makes classes that mainly hold data short and clear.

from dataclasses import dataclass, field

@dataclass
class Point:
    x: float
    y: float = 0.0
    tags: list = field(default_factory=list)      # mutable defaults need default_factory

p = Point(1.5)
print(p)                          # Point(x=1.5, y=0.0, tags=[])
print(p == Point(1.5))            # True

@dataclass(frozen=True)           # immutable and hashable
class Coordinate:
    lat: float
    lon: float
What is the difference between isinstance() and type()?
  • type(obj) == Cls checks for the exact class.
  • isinstance(obj, Cls) is True for the class and its subclasses, so it respects inheritance and is usually what you want.
  • issubclass(A, B) checks a relation between classes.
class Animal: ...
class Dog(Animal): ...

d = Dog()
print(type(d) == Animal, isinstance(d, Animal), issubclass(Dog, Animal))    # False True True
What is __slots__?

By default, each object stores its attributes in a dictionary (__dict__). Declaring __slots__ tells Python to use a fixed set of attributes instead, which reduces memory use and slightly speeds up attribute access, but you cannot add other attributes.

class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x, self.y = x, y

p = Point(1, 2)
# p.z = 3   ->  AttributeError

It is useful when you create millions of small objects.

What are mixins?

A mixin is a small class that provides extra behavior for other classes to inherit, and is not meant to be used on its own. It is a way to reuse functionality across unrelated classes without a deep hierarchy.

import json

class JsonMixin:
    def to_json(self):
        return json.dumps(self.__dict__)

class User(JsonMixin):
    def __init__(self, name):
        self.name = name

print(User("Asha").to_json())            # {"name": "Asha"}

What are some common design patterns in Python? (factory, strategy)

Many patterns are simpler in Python because functions and classes are first-class objects.

# Factory: create objects without exposing the class choice
class Dog:
    def speak(self): return "Woof"

class Cat:
    def speak(self): return "Meow"

def animal_factory(kind):
    return {"dog": Dog, "cat": Cat}[kind]()

# Strategy: swap the algorithm by passing a function
def total_price(prices, discount_rule):
    return sum(discount_rule(p) for p in prices)

print(animal_factory("cat").speak())                          # Meow
print(total_price([100, 200], lambda p: p * 0.9))             # 270.0

Other common ones: singleton, observer (callbacks and events), decorator (built into the language) and adapter.

Coding question: design a BankAccount class with encapsulation and validation.
class InsufficientFunds(Exception):
    pass

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self._balance = balance                 # protected by convention

    @property
    def balance(self):                          # read-only access
        return self._balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit must be positive")
        self._balance += amount

    def withdraw(self, amount):
        if amount > self._balance:
            raise InsufficientFunds("Not enough balance")
        self._balance -= amount

    def __repr__(self):
        return f"BankAccount({self.owner!r}, balance={self._balance})"

acc = BankAccount("Asha", 100)
acc.deposit(50)
acc.withdraw(30)
print(acc)                                       # BankAccount('Asha', balance=120)

It shows encapsulation (a private-by-convention balance and a read-only property), validation, a custom exception and __repr__. Interviewers often follow up by asking you to add an interest rate (inheritance), a transaction history (composition) or unit tests.
