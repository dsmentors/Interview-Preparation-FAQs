Complexity and fundamentals

Q1What is Big-O notation, and why does it matter?

Big-O notation describes how the running time (or memory) of an algorithm grows as the input size n grows, ignoring constants and smaller terms. It lets you compare algorithms independently of hardware and decide whether a solution will still work when the data becomes large.

For example, 3n² + 10n + 5 is simply O(n²), because for large n the n² term dominates.

Q3What is the difference between best, average and worst case complexity?
  • Best case: the most favorable input (for example the target is the first element in a linear search, O(1)).
  • Average case: the expected cost over typical inputs.
  • Worst case: the least favorable input (the target is last or missing, O(n)).

Interviews usually ask for the worst case unless stated otherwise. Big-O is an upper bound, Big-Omega a lower bound, and Big-Theta a tight bound.

Q4What is space complexity?

Space complexity is the extra memory an algorithm uses as the input grows, not counting the input itself. Creating a new list of size n is O(n), and a few variables is O(1). Recursion uses stack space: a recursion that goes n levels deep uses O(n) stack memory.

An algorithm that uses O(1) extra space is called in-place.

Q5How do you analyze the complexity of loops and recursion?
  • A single loop over n items is O(n); nested loops over n are O(n²).
  • A loop that halves the problem each time is O(log n).
  • Sequential blocks add up, and you keep the largest term.
  • For recursion, count the number of calls and the work per call: T(n) = 2T(n/2) + O(n) (merge sort) gives O(n log n), and T(n) = T(n-1) + T(n-2) (naive Fibonacci) gives O(2ⁿ).
def example(n):
    total = 0
    for i in range(n):              # O(n)
        total += i
    for i in range(n):              # nested loops: O(n^2)
        for j in range(n):
            total += i * j
    return total                    # overall: O(n^2), the larger term wins
Q6What is amortized time complexity?

Amortized complexity is the average cost per operation over a sequence of operations, even if a single operation is sometimes expensive. The classic example is appending to a dynamic array (a Python list): most appends are O(1), and occasionally the array has to be resized and copied (O(n)), but the average cost per append over many appends is O(1) amortized.

Python’s list is a dynamic array, which is why indexing and appending at the end are fast.

Q9How does a hash table (Python dict) work, and what are its complexities?

A hash table stores key-value pairs. A hash function converts the key into an integer index in an underlying array, so a value can be found directly.

  • Average lookup, insert and delete: O(1).
  • Worst case: O(n), if many keys collide into the same slot.
  • Collisions are handled by chaining (a list per slot) or open addressing (probing for another slot). Python’s dict uses open addressing.
  • Keys must be hashable (immutable), so lists cannot be keys but tuples can.
  • When the table gets too full, it is resized (rehashed), which is amortized O(1).
Q10What is the difference between a dict, a set and a list in Python in terms of lookup?

Checking x in my_list is O(n), because it scans the list. Checking x in my_set or x in my_dict is O(1) on average, because they use hashing. Converting a list to a set before many membership tests is one of the simplest and most common optimizations in interviews.

Q11Two Sum: given a list and a target, return the indices of two numbers that add up to the target.

Brute force checks every pair, O(n²). With a hash map, one pass is enough: for each number, check whether target - x has already been seen.

def two_sum(nums, target):
    seen = {}                               # value -> index
    for i, x in enumerate(nums):
        if target - x in seen:
            return seen[target - x], i
        seen[x] = i
    return None

Time O(n), space O(n).

Q12What is the two-pointer technique?

You keep two indexes that move through the data (usually from both ends, or one fast and one slow) to avoid a nested loop. It works well on sorted arrays, and for palindromes and in-place filtering.

def pair_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return left, right
        if s < target:
            left += 1
        else:
            right -= 1
    return None

Time O(n), space O(1).

Q13What is the sliding window technique? Find the length of the longest substring without repeating characters.

A sliding window keeps a range [start, i] that expands on the right and shrinks on the left to maintain a condition, giving O(n) instead of O(n²) for many subarray and substring problems.

def longest_unique_substring(s):
    last_seen = {}
    start = best = 0
    for i, ch in enumerate(s):
        if ch in last_seen and last_seen[ch] >= start:
            start = last_seen[ch] + 1       # move the window start past the repeated character
        last_seen[ch] = i
        best = max(best, i - start + 1)
    return best

For "abcabcbb" the answer is 3 ("abc"). Time O(n).

Q14What are prefix sums, and when are they useful?

A prefix sum array stores running totals, so the sum of any range can be computed in O(1) after O(n) preprocessing.

from itertools import accumulate

nums = [2, 4, 1, 3, 5]
prefix = [0] + list(accumulate(nums))        # prefix[i] = sum of the first i items

def range_sum(l, r):                          # sum of nums[l..r], inclusive
    return prefix[r + 1] - prefix[l]

print(range_sum(1, 3))                        # 4 + 1 + 3 = 8

They are useful for many range-query and subarray-sum problems.

Q15What is Kadane’s algorithm? Find the maximum sum of a contiguous subarray.

At each element, decide whether to extend the current subarray or start a new one:

def max_subarray(nums):
    best = current = nums[0]
    for x in nums[1:]:
        current = max(x, current + x)
        best = max(best, current)
    return best

print(max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]))     # 6  (subarray [4, -1, 2, 1])

Time O(n), space O(1). It is a simple example of dynamic programming.

Q16How do you group anagrams together?

Anagrams share the same sorted letters, so use the sorted word as a dictionary key.

from collections import defaultdict

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)
    return list(groups.values())

print(group_anagrams(["eat", "tea", "tan", "ate", "nat", "bat"]))

Time O(n · k log k) for n words of length k.

Linked lists, stacks, queues and heaps

Q17How do you reverse a singly linked list?

Walk through the list and flip each next pointer, keeping track of the previous node.

class Node:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def reverse_list(head):
    prev = None
    while head:
        nxt = head.next        # remember the rest of the list
        head.next = prev       # reverse the pointer
        prev = head
        head = nxt
    return prev

Time O(n), space O(1).

Q18How do you detect a cycle in a linked list?

Use Floyd’s tortoise and hare: a slow pointer moves one step and a fast pointer moves two steps. If there is a cycle, the fast pointer eventually meets the slow one.

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False

Time O(n), space O(1) (a set of visited nodes would also work, but uses O(n) space).

Q19What are a stack and a queue, and where are they used?
  • Stack (LIFO, last in first out): push and pop at the same end. Used for undo, the call stack, expression evaluation, and depth-first search. In Python, use a list (append and pop).
  • Queue (FIFO, first in first out): add at the back, remove from the front. Used for scheduling, buffering and breadth-first search. In Python, use collections.deque (append and popleft, both O(1)), since list.pop(0) is O(n).
Q20How do you check for valid parentheses?

Push each opening bracket on a stack, and when you see a closing bracket check that it matches the top of the stack.

def is_valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:
            stack.append(ch)
    return not stack

print(is_valid("{[()]}"), is_valid("(]"))      # True False

Time O(n), space O(n).

Q21How do you implement a queue using two stacks?

Use an inbox stack for pushes and an outbox stack for pops. When the outbox is empty, move everything from the inbox (which reverses the order).

class MyQueue:
    def __init__(self):
        self.inbox, self.outbox = [], []

    def push(self, x):
        self.inbox.append(x)

    def pop(self):
        if not self.outbox:
            while self.inbox:
                self.outbox.append(self.inbox.pop())
        return self.outbox.pop()

Each element is moved at most twice, so push and pop are O(1) amortized.

Q22What is a monotonic stack? Find the next greater element for each item.

A monotonic stack keeps its elements in increasing or decreasing order, which lets you answer “next greater/smaller element” questions in a single pass.

def next_greater(nums):
    result = [-1] * len(nums)
    stack = []                                  # indexes whose next greater element is not found yet
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            result[stack.pop()] = x
        stack.append(i)
    return result

print(next_greater([2, 1, 2, 4, 3]))            # [4, 2, 4, -1, -1]

Time O(n), because each index is pushed and popped once.

Q23What is a heap (priority queue)? How do you find the k largest elements?

A heap is a binary tree stored in an array where each parent is smaller (min-heap) or larger (max-heap) than its children. It gives the minimum (or maximum) in O(1), and push and pop in O(log n). Python’s heapq is a min-heap.

To find the k-th largest, keep a min-heap of size k:

import heapq

def kth_largest(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)             # drop the smallest of the k+1 items
    return heap[0]

print(kth_largest([3, 2, 1, 5, 6, 4], 2))   # 5
print(heapq.nlargest(2, [3, 2, 1, 5, 6, 4]))   # [6, 5]

Time O(n log k), which is better than sorting (O(n log n)) when k is small.

Q24How would you design an LRU cache?

An LRU (Least Recently Used) cache needs O(1) get and put, and must evict the item that has not been used for the longest time. Combine a hash map (fast lookup) with a doubly linked list (fast reordering). In Python, OrderedDict does both:

from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.data = OrderedDict()

    def get(self, key):
        if key not in self.data:
            return -1
        self.data.move_to_end(key)          # mark as most recently used
        return self.data[key]

    def put(self, key, value):
        self.data[key] = value
        self.data.move_to_end(key)
        if len(self.data) > self.cap:
            self.data.popitem(last=False)   # evict the least recently used

Trees and graphs

Q25What is a binary tree, and what is a binary search tree (BST)?

A binary tree is a tree where each node has at most two children (left and right). A binary search tree adds an ordering rule: for every node, all values in the left subtree are smaller and all values in the right subtree are larger.

In a balanced BST, search, insert and delete are O(log n). In the worst case (a skewed tree, for example inserting sorted data) they degrade to O(n).

Q26What are the tree traversals?
Traversal Order Typical use
Inorder Left, node, right Gives a BST’s values in sorted order
Preorder Node, left, right Copying or serializing a tree
Postorder Left, right, node Deleting a tree, evaluating expressions
Level order (BFS) Level by level Shortest depth, printing by levels 
from collections import deque

class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def inorder(root):
    return inorder(root.left) + [root.val] + inorder(root.right) if root else []

def level_order(root):
    result, queue = [], deque([root] if root else [])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result
Q27How do you find the maximum depth (height) of a binary tree?

The depth of a tree is 1 + the larger depth of its two subtrees:

def max_depth(root):
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))

Time O(n), and the space is O(h) for the recursion, where h is the height of the tree.

Q28How do you check whether a binary tree is a valid BST?

It is not enough to compare each node with its children. Every node must stay within a valid range inherited from its ancestors:

def is_bst(node, low=float("-inf"), high=float("inf")):
    if not node:
        return True
    if not (low < node.val < high):
        return False
    return is_bst(node.left, low, node.val) and is_bst(node.right, node.val, high)

An alternative is to do an inorder traversal and check that the values are strictly increasing.

Q29What are balanced trees (AVL, Red-Black), and what is a trie?
  • AVL and Red-Black trees are self-balancing BSTs: they rotate nodes after inserts and deletes so the height stays O(log n), which guarantees O(log n) operations. They are used in ordered maps and sets in many libraries.
  • A trie (prefix tree) stores strings character by character, so words with a common prefix share a path. Lookups take O(length of the word). It is used for autocomplete, spell checking and prefix search.

Q31What is the difference between BFS and DFS?
BFS (Breadth-First Search) DFS (Depth-First Search)
Explores Level by level (nearest first) As deep as possible before backtracking
Data structure Queue Stack or recursion
Finds shortest path (unweighted) Yes No
Typical use Shortest path, level order, “minimum steps” problems Cycle detection, topological sort, connected components, backtracking
Time O(V + E) O(V + E) 
from collections import deque

graph = {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}

def bfs(start):
    seen, order, queue = {start}, [], deque([start])
    while queue:
        node = queue.popleft()
        order.append(node)
        for nb in graph[node]:
            if nb not in seen:
                seen.add(nb)
                queue.append(nb)
    return order

def dfs(node, seen=None):
    seen = seen if seen is not None else set()
    seen.add(node)
    for nb in graph[node]:
        if nb not in seen:
            dfs(nb, seen)
    return seen

print(bfs("A"))        # ['A', 'B', 'C', 'D']
Q32How do you find the shortest path in a weighted graph (Dijkstra’s algorithm)?

Dijkstra’s algorithm repeatedly takes the closest unvisited node (using a min-heap) and relaxes the distances to its neighbors. It works for graphs with non-negative edge weights.

import heapq

def dijkstra(graph, source):
    # graph: {node: [(neighbor, weight), ...]}
    dist = {node: float("inf") for node in graph}
    dist[source] = 0
    heap = [(0, source)]
    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]:
            continue                          # an older, longer entry
        for nb, w in graph[node]:
            nd = d + w
            if nd < dist[nb]:
                dist[nb] = nd
                heapq.heappush(heap, (nd, nb))
    return dist

Time O((V + E) log V). For negative weights, use Bellman-Ford (O(V·E)). For an unweighted graph, plain BFS is enough.

Q33What is topological sorting, and how do you do it?

A topological sort orders the nodes of a directed acyclic graph (DAG) so that every edge u → v has u before v. It is used for task scheduling, build order and course prerequisites. Kahn’s algorithm repeatedly removes nodes with no incoming edges:

from collections import deque

def topological_sort(graph):
    # graph: {node: [neighbors]}; the edge u -> v means u must come before v
    indegree = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            indegree[v] += 1
    queue = deque(u for u in graph if indegree[u] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)
    return order if len(order) == len(graph) else None      # None means there is a cycle
Q34What is Union-Find (disjoint set), and when is it used?

Union-Find tracks which elements belong to the same group and supports find (which group?) and union (merge groups) in nearly constant time with path compression. It is used for connected components, detecting cycles in undirected graphs and Kruskal’s minimum spanning tree.

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]     # path compression
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                                      # already connected
        self.parent[rb] = ra
        return True
Q35What is a minimum spanning tree (MST)? What are Kruskal’s and Prim’s algorithms?

A spanning tree connects all nodes of a graph without cycles, and the MST is the one with the smallest total edge weight (used for network and cable design).

  • Kruskal’s: sort all edges by weight and add each one if it does not create a cycle (checked with Union-Find). Good for sparse graphs.
  • Prim’s: start from one node and repeatedly add the cheapest edge that connects a new node (using a min-heap).

Both are greedy and run in about O(E log V).

Q37How do merge sort and quick sort work?
  • Merge sort (divide and conquer): split the list in half, sort each half recursively, then merge the two sorted halves. Always O(n log n), but needs O(n) extra space.
  • Quick sort: choose a pivot, put smaller items on one side and larger on the other, and sort each side recursively. O(n log n) on average, but O(n²) in the worst case (for example a bad pivot on sorted data), so a random or median pivot helps.
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    merged, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    return merged + left[i:] + right[j:]

def quick_sort(a):                               # simple version, not in-place
    if len(a) <= 1:
        return a
    pivot = a[len(a) // 2]
    return (quick_sort([x for x in a if x < pivot])
            + [x for x in a if x == pivot]
            + quick_sort([x for x in a if x > pivot]))
Q38How does binary search work, and when can you use it?

Binary search finds a target in a sorted list by repeatedly halving the search range.

def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

Time O(log n), space O(1). Python has bisect for this. Binary search also works on any monotonic condition, for example finding the smallest value for which a condition becomes true (“binary search on the answer”).

Q39What is recursion, and what are its risks?

Recursion is when a function calls itself on a smaller version of the problem. It needs a base case (to stop) and a recursive step that moves toward it. Risks: a missing base case causes infinite recursion, deep recursion can overflow the stack (Python’s default limit is about 1,000 calls), and naive recursion can repeat work (as in Fibonacci), which memoization fixes. Any recursion can be converted to a loop with an explicit stack.

Q40What is backtracking? Generate all subsets of a list.

Backtracking builds a solution step by step, and undoes (backtracks) a choice when it leads to a dead end or after exploring it. It is used for subsets, permutations, N-Queens, Sudoku and word search.

def subsets(nums):
    result = []

    def backtrack(start, path):
        result.append(path[:])               # record the current subset
        for i in range(start, len(nums)):
            path.append(nums[i])             # choose
            backtrack(i + 1, path)           # explore
            path.pop()                       # undo the choice

    backtrack(0, [])
    return result

print(subsets([1, 2, 3]))     # 8 subsets, from [] to [1, 2, 3]

Time O(2ⁿ). Pruning invalid branches early makes it much faster in practice.

Q41What is divide and conquer?

It splits a problem into smaller independent subproblems, solves each (usually recursively), and combines the results. Examples: merge sort, quick sort, binary search and fast exponentiation. Compare with dynamic programming, where the subproblems overlap.

Q42Why is searching in a sorted structure faster, and which structures give O(log n) search?

Because sorted order lets you discard half of the remaining data with every comparison. Structures that give O(log n) search: sorted arrays (binary search), balanced BSTs (AVL, Red-Black, and sorted containers in some libraries), and heaps for the min or max only. Hash tables give O(1) average lookup, but without any ordering.

Dynamic programming and greedy algorithms

Q43What is dynamic programming (DP)?

DP solves a problem by breaking it into overlapping subproblems and storing their results, so each one is solved only once. A problem is suited to DP when it has:

  1. Overlapping subproblems: the same subproblem appears many times.
  2. Optimal substructure: the best solution is built from the best solutions of its subproblems.

A typical process: define the state, write the recurrence (transition), choose the base cases, and decide the order of computation.

Q44What is the difference between memoization and tabulation?
Memoization (top-down) Tabulation (bottom-up)
Approach Recursion with a cache Iterative, fill a table from the smallest subproblems
Computes Only the subproblems that are needed All subproblems
Overhead Recursion calls and stack depth None, and easier to optimize space 
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):                                   # memoization
    return n if n < 2 else fib(n - 1) + fib(n - 2)

def fib_tab(n):                               # tabulation with O(1) space
    if n < 2:
        return n
    a, b = 0, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b

Naive Fibonacci is O(2ⁿ), and with memoization or tabulation it is O(n).

Q45Coin change: find the minimum number of coins that make up an amount.

dp[a] is the minimum number of coins needed for amount a. For each amount, try every coin: dp[a] = min(dp[a], dp[a - coin] + 1).

def coin_change(coins, amount):
    dp = [0] + [float("inf")] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != float("inf") else -1

print(coin_change([1, 2, 5], 11))     # 3  (5 + 5 + 1)

Time O(amount × number of coins). A greedy “largest coin first” approach does not always work for arbitrary coin sets, but DP does.

Q460/1 knapsack: choose items to maximize value within a weight limit.

dp[c] is the best value achievable with capacity c. Process each item, and loop the capacity backwards, so that each item is used at most once.

def knapsack(weights, values, capacity):
    dp = [0] * (capacity + 1)
    for w, v in zip(weights, values):
        for c in range(capacity, w - 1, -1):
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[capacity]

print(knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7))     # 9

Time O(n × capacity).

Q47Longest Common Subsequence (LCS): how do you solve it with DP?

dp[i][j] is the LCS length of the first i characters of a and the first j characters of b. If the characters match, extend the diagonal; otherwise take the better of dropping a character from either string.

def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

print(lcs("abcde", "ace"))      # 3

Time and space O(len(a) × len(b)). The same idea underlies edit distance and diff tools.

Q48What is a greedy algorithm, and how is it different from DP?

A greedy algorithm makes the locally best choice at each step, hoping to reach the global optimum, and never reconsiders. It is simple and fast, but is only correct when the problem has the greedy-choice property (proven for the problem).

Greedy Dynamic programming
Decisions One choice per step, final Considers all subproblem results
Speed Usually faster Usually slower, more memory
Correctness Only for certain problems Works whenever there is optimal substructure
Examples Interval scheduling, Huffman coding, Dijkstra, Kruskal Knapsack, LCS, coin change (general case)
Q49Interval scheduling: select the maximum number of non-overlapping intervals.

The greedy rule is to always pick the interval that finishes earliest, because it leaves the most room for the others.

def max_non_overlapping(intervals):
    intervals.sort(key=lambda x: x[1])             # sort by end time
    count, end = 0, float("-inf")
    for s, e in intervals:
        if s >= end:
            count += 1
            end = e
    return count

print(max_non_overlapping([(1, 3), (2, 4), (3, 5), (0, 6), (5, 7)]))     # 3

Time O(n log n), for the sort.

Q50How do you approach a coding interview problem?
  1. Clarify the problem: inputs, outputs, constraints, edge cases, and ask for examples.
  2. Start with a brute-force idea and state its complexity.
  3. Optimize: look for a pattern (hash map, two pointers, sorting, heap, binary search, DP...) and justify the improvement.
  4. Confirm the plan with the interviewer before writing code.
  5. Write clean code with meaningful names, and talk through your thinking.
  6. Test with a normal case and edge cases (empty input, one element, duplicates, negative numbers, very large input).
  7. State the final time and space complexity.

Q52What edge cases should you always consider?
  • Empty input (empty list, empty string, None).
  • A single element.
  • Duplicates and all equal values.
  • Negative numbers and zeros.
  • Already sorted or reverse-sorted input.

Q55Where are data structures and algorithms used in data science and machine learning?
  • Hash tables: dictionaries, pandas indexes, feature hashing, counting and group-bys.
  • Arrays and matrices: NumPy and tensors, with vectorized operations instead of Python loops.
  • Heaps: top-k recommendations, beam search, priority scheduling.
  • Trees: decision trees and random forests, KD-trees and ball trees for nearest-neighbor search, tries for autocomplete.

Understanding complexity also helps you write code that scales to large datasets.

Q56How do you prepare for DSA interviews effectively?
  • Learn the core data structures and the main patterns (see the table above) before grinding hundreds of problems.
  • Practice by topic, then mix topics, on platforms such as LeetCode, HackerRank or similar.
  • Solve, then review: study the best solutions and note the pattern.
  • Code by hand or in a plain editor at times, and time yourself.
  • Explain aloud while solving, because communication is part of the evaluation.
  • Revisit problems you failed after a few days (spaced repetition).
